# Course & Training Management System (Курсовой проект / ИПР №1)

Комплексный безопасный REST API для системы записи на курсы и тренинги с оплатой, личным кабинетом студента, кабинетом преподавателя и динамическим RBAC (Role-Based Access Control).

Проект разработан в строгом соответствии с требованиями **OWASP Top 10** и спецификацией **ИПР №1**.

---

## 🚀 Быстрый запуск на локальном компьютере

### 1. Требования к окружению
* **Node.js**: версия 18, 20 или 22+ (рекомендуется LTS).
* **npm** (поставляется вместе с Node.js).
* Не требуется установка внешних СУБД: по умолчанию из коробки используется встроенный движок SQLite. При необходимости можно подключить внешний PostgreSQL через переменную `DATABASE_URL`.

---

### 2. Пошаговые команды для запуска

Откройте терминал в папке проекта и выполните 3 шага:

```bash
# Шаг 1. Установка всех зависимостей
npm install

# Шаг 2. Создание файла конфигурации окружения
cp .env.example .env

# Шаг 3. Запуск сервера разработки
npm run dev
```

После этого сервер запустится по адресу: **http://localhost:3000**

При первом запуске сервер **автоматически**:
1. Создаст таблицы базы данных со всеми внешними ключами и ограничениями целостности.
2. Проведет сидинг (наполнит базу 16 атомарными правами, ролями `admin`, `instructor`, `student`, тестовыми пользователями и демонстрационными курсами).
3. Смонтирует интерактивный UI разработчика, Swagger UI и эндпоинты API.

## 🛡️ Реализованные меры безопасности (OWASP)

1. **Пункт 5: JWT в httpOnly Cookies**:
   * Access-токен (время жизни 15 минут) передается в теле ответа и заголовке `Authorization: Bearer`.
   * Refresh-токен (время жизни 7 дней) защищен атрибутами `httpOnly`, `Secure`, `SameSite=Strict`.
2. **Пункт 6: Защита от брутфорса**:
   * После 5 неудачных попыток ввода пароля учетная запись блокируется на 15 минут (поле `lock_until` в БД, HTTP-код 423 Locked).
   * Действует дополнительный лимитер `express-rate-limit` на IP-адрес.
3. **Пункт 14: Шифрование данных карт AES-256-GCM**:
   * Номер банковской карты и CVV шифруются симметричным алгоритмом AES-256-GCM ключом из `.env`.
   * В API клиенту отдаются только маскированные 4 последние цифры (`last4`). Зашифрованный payload недоступен через публичные эндпоинты.
4. **Пункт 24: Generic Errors в продакшене**:
   * Исключены утечки внутренних стектрейсов и деталей SQL-запросов.
5. **Динамический RBAC**:
   * Маршруты проверяют атомарные права (`hasPermission('courses:create')`), а не жестко зашитые имена ролей в коде.

## 🧪 Тестирование через Postman

1. Откройте **Postman** и нажмите кнопку **Import**.
2. Выберите файл `postman/course_management_api.json` из корня проекта (или скачайте по адресу `http://localhost:3000/api/postman-collection`).
3. Запустите готовые сценарии:
   * **`1. Authentication & Security`** -> `Login as Admin` (скрипт автоматически запишет токен в переменную `{{accessToken}}`).
   * **`2. Dynamic RBAC`** -> `[Negative Test] Student attempts to access /roles` (проверка получения HTTP 403 Forbidden).
   * **`6. Bank Cards & AES-256`** -> привязка карты и проверка маскирования `last4`.
   * **`5. Enrollments` & `7. Payments`** -> бронирование места на курсе и проведение оплаты.
